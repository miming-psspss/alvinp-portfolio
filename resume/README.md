# Resume / CV

Three tailored versions, same underlying experience, different framing depending on the role.
All three are generated from a single source of truth — `MASTER_RESUME.md` — rather than
maintained by hand in parallel, so facts (dates, project bullets, competencies) stay
consistent across versions.

| [`Alvin_Piquero_Resume_AI Automation Specialist_8-27-2026.pdf`](<./Alvin_Piquero_Resume_AI Automation Specialist_8-27-2026.pdf>) | AI/automation specialist framing — leads with the Python/VBA automation systems and the CAS project |
| [`CV_AlvinPiquero_BusinessAnalyst.pdf`](./CV_AlvinPiquero_BusinessAnalyst.pdf) | Business analyst framing — leads with process improvement, requirements, and the data migration accuracy work |
| [`Alvin_Piquero_BusinessOperationsSpecialist.pdf`](./Alvin_Piquero_BusinessOperationsSpecialist.pdf) | Business operations framing — leads with the cooperative operations context and cross-functional support work |

## Source of truth

[`MASTER_RESUME.md`](./MASTER_RESUME.md) holds every fact, summary variant, competency,
project bullet, and experience bullet used across all three PDFs, plus a change log. When
a fact changes (a new project, an updated cert, a corrected date), it's edited once in the
master document and the tailored versions are regenerated from it — not edited individually.
